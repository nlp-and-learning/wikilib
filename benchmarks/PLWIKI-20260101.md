# Polish Wikipedia: bounded real-dump measurements

Measured on 2026-10-06, Linux x86-64, AMD Ryzen 9 9900X, GCC 15.2,
CMake Release, libbz2 1.0.8. Three fresh processes per configuration;
filesystem cache is warm. Times below are medians; RSS is the maximum Linux
`getrusage(RUSAGE_SELF).ru_maxrss` across three runs.

## Input and scope

`plwiki-20260101-pages-articles-multistream.xml.bz2` is **2,800,628,387 bytes**
(2.61 GiB compressed), rather than 29 GB. Its compressed index is 29,102,752
bytes, containing 2,821,590 pages in 28,220 chunks. The entire index was scanned;
the entire XML dump was not decompressed.

The sample comprises first 10 chunks, first 10 starting at/after the compressed
file midpoint, and last 10 chunks. These contain **2,943 pages**, **6,180,082
compressed bytes** (5.89 MiB), and **20,699,085 decoded content bytes** (19.74 MiB).
The three contiguous groups have byte ranges `[634,4224253)`,
`[1400440882,1401404079)`, and `[2799635121,2800628387)`.
[Selection metadata](plwiki-20260101-selection.json) records every chunk range.
The initial siteinfo-only BZ2 member is outside the index sample.

A 128 MiB compressed-read budget applies **per operation**, including repeated
reads by single-page extraction. Total traffic across all repeated measurements
is larger. Original files are opened read-only; temporary symlinks, extracted
parser samples, and plans live under `/tmp`.

## Index, XML, cancellation, and markup

| Operation | Median seconds | Maximum RSS (MiB) |
| --- | ---: | ---: |
| Stream entire index, discard chunks | 2.1268 | 10.50 |
| Load entire title map | 3.3729 | 508.11 |
| Stream selected XML chunks | 0.4893 | 11.95 |
| Decompress and parse each whole selected chunk | 0.4490 | 15.00 |
| Cancel after 10 pages | 0.0173 | 10.16 |
| Parse 30 wikitext samples and build section trees | 0.0301 | 20.68 |

Streaming XML throughput is about 40.3 MiB/s of decoded content in this sample;
buffered processing is about 44.0 MiB/s. These are small real chunks, so the
memory gap is modest; the synthetic large-chunk report tests larger XML buffers.
Streaming retains current page text and chunk index entries. It is not constant
memory with respect to arbitrarily large individual pages.

Cancellation delivered exactly 10 callbacks, read 262,144 compressed bytes
(including buffering/read-ahead), and reported cancellation without an error.

Markup samples are the 10 smallest nonempty pages, 10 closest to 4 KiB, and 10
largest pages up to 1 MiB from the selected chunks, deduplicated by ID. They range
from 13 to 900,173 bytes, totaling 3,080,793 bytes. All 30 returned ASTs and
section trees, containing 517 sections. Bydgoszcz (ID 493) and Bielsko-Biała
(ID 632) each reported `Unexpected token without parser progress`; recovery
completed. Their trees have 157 and 56 sections respectively. These diagnostics
remain a follow-up for parser fidelity. Tree creation alone does not validate
all semantics or match rendered MediaWiki output. Template expansion and Lua
were not exercised.

## Extraction

Times exclude loading the full title map, which costs roughly 3.4 seconds per
fresh process. Total times, RSS, and compressed byte counts are in the raw data.
`same` requests pages from one chunk; `spread` distributes requests round-robin
across the sampled chunks. Requested order is reversed and checked by checksum.
Results are checked against per-page hashes from the streaming sample.

| Distribution | Pages | Batch seconds | Separate calls seconds | Speedup |
| --- | ---: | ---: | ---: | ---: |
| same | 1 | 0.0409 | 0.0406 | 1.0× |
| same | 10 | 0.0411 | 0.4009 | 9.7× |
| same | 100 | 0.0436 | 4.0319 | 92.5× |
| spread | 1 | 0.0410 | 0.0402 | 1.0× |
| spread | 10 | 0.3252 | 0.3272 | 1.0× |
| spread | 100 | 0.4761 | 1.7426 | 3.7× |

The loaded map dominates extraction RSS (about 509–513 MiB). Batch requests
parse each distinct chunk once. Ten spread requests touch ten distinct chunks,
so there is little batching benefit; 100 spread requests reuse chunks and do
benefit. Reuse a loaded `DumpReader` for subsequent requests, or use
`IndexChunker` plus `process_chunk()` when a full title lookup map is unnecessary.

## Correctness finding and verification

The initial real-file run stopped because index title
`Gnieźnieńska Wyższa Szkoła Humanistyczno-Menedżerska &quot;Milenium&quot;`
did not match the decoded XML title. The index parser now decodes predefined XML
entities exactly once, preserving literal entity-looking title text encoded via
`&amp;`. Two regression tests cover normalization, chunk lookup, streaming,
and extraction by decoded title. Mismatch errors now include chunk position,
IDs, and titles for diagnosis.

After the fix, streaming and independent buffered/pugixml extraction match page
counts, title order, content sizes, and FNV-1a checksums. Batch/single checksums
match for every configuration. All 54 measurements passed the verification
script. Checksums detect accidental differences; they are not cryptographic
proof of equality. The full CTest suite has 497 passing tests and 8 skipped
DumpPath tests. A final rebuild and sample replay also returned the same XML
checksum.

[Raw results](plwiki-20260101-results.jsonl) contain all measured runs.
These bounded samples do not prove every chunk is valid or measure full-dump
wall time; no full-dump throughput estimate is made.

## Reproduce

Dependencies are the library's normal system development packages. From the
repository root:

```sh
cmake -S . -B /tmp/wikilib-real-benchmark-build \
  -DCMAKE_BUILD_TYPE=Release -DWIKILIB_BUILD_TESTS=OFF \
  -DWIKILIB_BUILD_EXAMPLES=OFF -DWIKILIB_BUILD_BENCHMARKS=ON
cmake --build /tmp/wikilib-real-benchmark-build -j4
/tmp/wikilib-real-benchmark-build/bin/benchmark_real_dump prepare \
  /home/andrzej/dump/wiki/plwiki-20260101-pages-articles-multistream.xml.bz2 \
  /home/andrzej/dump/wiki/plwiki-20260101-pages-articles-multistream-index.txt.bz2 \
  /tmp/wikilib-plwiki-benchmark /tmp/wikilib-plwiki-plan.json
bash benchmarks/run_real.sh \
  /tmp/wikilib-real-benchmark-build/bin/benchmark_real_dump \
  /tmp/wikilib-plwiki-plan.json /tmp/plwiki-results.jsonl
```

The runner creates temporary samples/references before timed runs and imposes a
60-second timeout on each measurement. It writes JSONL plus adjacent auxiliary
sample/diagnostic files. `verify_real.py` checks result agreement and budgets.
Peak RSS includes the decoded selection plan/runtime; preparing it precedes the
reported operation timers. Parser timings include reading saved sample files.
